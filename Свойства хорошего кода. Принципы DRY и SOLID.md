### Свойства хорошего кода

Код считается хорошим, если он обладает свойствами:
- В нем легко разобраться стороннему разработчику
- Код легко расширять и добавлять новый функционал в программу
- Код легко менять с целью устранения багов или в качестве поддержки при изменении стороннего кода, выхода новых версий библиотек и т.п.


### DRY

DRY - Dont Repeat Yourself - не повторяйся
Логически связанные блоки кода нужно объединять в функции и переиспользовать их, чтобы избегать дублирования


### SOLID

SOLID - аббревиатура, означающая пять основных принципов проектирования объектно-ориентированной парадигме:
- Single responsibility principle / Принцип единственной ответственности 
- Open-closed principle / Принцип открытости/закрытости
- Liskov substitution principle  / Принцип подстановки Лисков
- Interface segregation principle / Принцип разделения интерфейса
- Dependency inversion principle / Принцип инверсии зависимостей
Соблюдение принципов позволяет разрабатывать программы, которые будет проще расширять и поддерживать. 


### Принцип единственной ответственности

Принцип единственной ответственности говорит о том, что класс должен иметь лишь одно предназначение и должен полностью инкапсулировать все необходимое, но не сверх того, внутри себя
Проще говоря, у класса должна быть только одна причина для изменения

В качестве примера можно рассмотреть задачу представления каких-либо данных для пользователя
В этой задаче выделяются две функции:
- Хранение, чтение и запись данных, например в базе данных
- Формат представления данных, например HTML, XML, JSON
Принцип единственной ответственности говорит о том, что обе функции нельзя объединять в один класс, а нужно выделять в разные классы
